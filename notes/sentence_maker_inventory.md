## How the Sentence Maker actually works

This took some archaeology. The plan's working assumption that the Excel encoded Khuzdul morphology (triconsonantal roots, broken plurals, construct state, etc.) is **wrong**. The workbook contains **no morphology layer at all** — no roots index, no inflection patterns, no pronoun affixes, no grammar.

What it actually is:

1. A **flat dictionary of ~215,000 English→Neo-Khuzdul phrase pairs**, where each entry's English side is annotated with a bracketed grammatical tag (e.g. `abdicate [Intensifying Imperfect]`, `abdicate! [Imperative Plural]`). All inflected forms are pre-enumerated as separate dictionary entries; the user picks the inflection they want by typing the bracket-tagged English.
2. A **phonetic-orthography pipeline** that takes the dictionary's Khuzdul rendering (with markup like `_`, `-`, `(ul)`) and produces (a) an IPA-style phonetic transcription with schwa epenthesis, long-vowel caret, and gemination applied, and (b) two Cirth renderings (Angerthas Moria and Angerthas Erebor) keyed to font-specific codepoints.

This is the **right** thing to port for Phase 0 of the master plan: it gives us a deterministic Khuzdul phrase-lookup tool plus authoritative phonology and Cirth conversion. Morphology lives elsewhere (the Dwarrow Scholar's grammar PDFs) and is a Phase 1 corpus-assembly task — not a Step-3 module here.

### Stage-by-stage

1. **Dictionary lookup** (CONSTRUCT, exact match). VLOOKUP against `$A:$B` with the 4th argument `0` (exact). Multi-word phrases work because column A holds full phrases, not single words.
2. **Markup strip** (Converter, `=SUBSTITUTE(SUBSTITUTE(SUBSTITUTE(AL6,"_",""),"-",""),"(ul)","")`). The dictionary's Khuzdul strings carry three kinds of in-band markup which the user wants stripped from the phonetic rendering: `_` (something internal), `-` (clitic boundary; restored later if originally present at string edges), `(ul)` (an alternate-form marker).
3. **Per-character romanization** (Converter, ~30 columns each for 30 word slots). Each character of the cleaned Khuzdul is looked up in `Phonetics and Cirth!C3:J55` column 7, returning an `AM00x` code. Special case: `'` → `AM001` (glottal stop). Padded with `"space"` for spaces.
4. **Digraph collapse** (Converter `CK6:DD6` etc.). A two-character sliding window detects 16 digraphs (`ch sh kh gh dh hw hy lh ng nd nj ts ps ks zh` plus an extra `AM039/AM005` overlap) and emits the digraph's AM-code at the first position while the second position is blanked. Not a longest-match scan in the usual sense — implemented as a positional rewrite where each column checks "did my predecessor consume me?" via the outer `IF(OR(prev=digraph_code), "", ...)`.
5. **Three parallel VLOOKUPs into Phonetics and Cirth** (Converter). For each AM code, fetch:
   - column 4 — Angerthas Moria font glyph (single Latin char, e.g. `g`, `2`, `#`)
   - column 6 — Angerthas Erebor font glyph (same scheme, different mapping)
   - column 13 — IPA symbol (e.g. `b`, `kʰ`, `d͡ʒ`, `ə`)
6. **Concatenate per-word strings and re-attach hyphens.** Converter `FY6/FZ6/GA6/GB6` re-add hyphens that were stripped if the input started/ended with `-`.
7. **Phonological rewrites** (Shwa-Caret-Gemination). The IPA-bracketed string `[…]` feeds into a long pipeline of `SUBSTITUTE` calls keyed to the rule tables in this sheet. Four rule families based on column groups:
   - **END SHWA** (cols A→B, ~700 rows): bigram-final patterns like `bb]` → `bəb]`. The `]` is the IPA word-boundary marker.
   - **MID SHWA** (cols J→K, ~700 rows): bigram-medial patterns like `bbb` → `bəbb`.
   - **Caret** (cols CC, CE, etc.): long-vowel marker handling.
   - **Gemination** (cols CH, CJ, etc.): consonant-doubling. Output of the gemination cascade lands in column `CJ`, and CONSTRUCT row 4 reads from `Shwa-Caret-Gemination!$CJ_N`.
   - The 68,460 rows aren't 68K rules — each rule has many bigram instantiations across all phoneme pairs. The actual rule count will resolve to ~89 distinct substitutions per pipeline stage (matching the SUBSTITUTE nesting depth observed in the F2/G2/H2/N2/O2/P2 formulas).
8. **Sentence assembly** (CONCAT). Five `=TRIM(CONCATENATE(…30 cells with separator A1…))` formulas, with light cleanup substitutions (e.g. `dʊ] [ɑ` → `dɑ` to glue across word boundaries in IPA; `du a` → `d' a` in Khuzdul).
9. **Display copy** (VBA `FINAL4`, manual). The user clicks a macro button; CONCAT!C1:C5 → FINAL!B1:B5 as values.

## Caveats discovered

- **Dictionary uses non-ASCII heavily**: `'` (apostrophe-as-glottal-stop), macrons (`â`, `ê`, `î`, `ô`, `û`), diaereses (`ö`, `ü`), grave (`è`, `ù`), `ŋ`, and the schwa `ə` in the phonological-rule tables. Everything must be NFC normalized in the JSON dump.
- **The Cirth glyph columns hold font-keyed characters**, not Unicode runes. E.g., `g` in the Angerthas Moria column means "the glyph that the AM-keyed Cirth font renders for the Latin character `g`." Without the font installed, Cirth output is meaningless ASCII. The port should either (a) map to Unicode Cirth at U+16A0..U+16F8 by joining a separate `am_code → unicode_codepoint` table, or (b) bundle SVG glyphs.
- **CONSTRUCT row 1 reverses the lookup direction**: `H1 = VLOOKUP(H2, $A:$C, 3, 0)` returns the *cleaned* English (column C). This is for redisplaying "what the user typed" with the bracketed annotation removed, so the English line of the FINAL output reads cleanly.
- **Spot/PICK NUMBER mechanic** (CONSTRUCT cells S8/U8/W8 and AN7/AN8): when a typed English string matches multiple dictionary entries (substring search), the user can pick which one to use by setting a "PICK NUMBER" cell. The substring-search ranking is in columns D, E, F (`SEARCH` + `RANK`). For the Python port, this becomes "lookup returns a `list[DictionaryEntry]` and the caller picks; default is the first."
- **The original Excel has a 30-word input cap** (columns H..AK = 30). The Python port should remove this limit.

## Architecture for the Python port

Given the simpler-than-expected reality of the workbook, the package shape becomes:

```
khuzdul_translator/
├── __init__.py
├── data/
│   ├── dictionary.json           # 215K entries with cleaned English + tag
│   ├── phonemes.json             # 53 entries; AM/AE codes, IPA, Cirth chars
│   ├── digraphs.json             # 16 digraph collapse rules
│   ├── phonological_rules.json   # 4 rule families: end-shwa, mid-shwa, caret, gemination
│   └── cirth_unicode_map.json    # AM/AE code → Unicode Cirth codepoint (built by us; see Step 2.5)
├── lexicon.py                    # load dictionary, exact lookup, substring rank
├── romanize.py                   # markup-strip + AM-code split + digraph collapse
├── phonology.py                  # apply 4 rule families to an IPA string
├── cirth.py                      # AM/AE code → Unicode (or bundled SVG glyph)
├── pipeline.py                   # the end-to-end translate() function
├── cli.py                        # `python -m khuzdul_translator "the dwarves dig deep"`
└── tests/
    ├── gold_set.json             # 20 hand-translated sentences
    ├── test_lexicon.py
    ├── test_romanize.py
    ├── test_phonology.py
    ├── test_cirth.py
    └── test_pipeline.py
```

Module changes from the original port plan:

- **No `morphology.py`** — there is no morphology layer in the workbook. (Defer the Dwarrow Scholar's grammar to the Phase 1 corpus pipeline.)
- **No `grammar.py`** — no sentence-level orchestration is needed; translation is word-by-word phrase lookup. (spaCy is **not** required for Step 1; lemmatization would degrade lookup quality because the dictionary already keys on bracket-tagged inflected forms.)
- **New `romanize.py`** — the work of stages 2–4 (markup strip, per-char AM code lookup, digraph collapse).
- **New `phonology.py`** — applies the ~89 substitutions in the four rule families to the IPA-bracketed string.
- **`cirth.py` gains an extra responsibility**: map from AM/AE font-keyed glyph back to a stable Unicode (or SVG) representation, because the workbook's column-4 / column-6 outputs are font-specific Latin characters, not Unicode Cirth.

## Trace of one (hypothetical) translation

User types `dwarves` into `CONSTRUCT!H2`. (We have not run an interactive test against the live Excel yet — that's a Step 4 task with the 20-sentence gold set.)

1. `CONSTRUCT!H3 = VLOOKUP("dwarves", $A:$B, 2, 0)` → some Khuzdul word, e.g. `Khazâd` (correct form per Tolkien; the dictionary may use a different inflected form).
2. `Converter!AL6 = "Khazâd"`, `AN6 = "Khazâd"` (no markup to strip).
3. `Converter!AW6..BB6 = "K", "h", "a", "z", "â", "d"` (six characters).
4. `BQ6..BV6 = AM020, AM014, AM002, AM048, AM003, AM006` (Latin → AM code).
5. `CK6..CP6` = digraph collapse: `kh` detected at position 1+2 → `CK6 = AM021` (kh), `CL6 = ""`. Then `CM6 = AM002` (a), `CN6 = AM048` (z), `CO6 = AM003` (â), `CP6 = AM006` (d).
6. Three parallel VLOOKUPs against `Phonetics and Cirth`:
   - Moria glyphs: `eV`, `c`, `w`, `v`, `9` → joined as `eVcwv9`
   - Erebor glyphs: `t`, `c`, `D`, `v`, `9` → joined as `tcDv9`
   - IPA: `kʰ`, `ɑ`, `z`, `ɑ:`, `d` → joined as `[kʰɑzɑ:d]`
7. Shwa-Caret-Gemination applies its substitutions to `[kʰɑzɑ:d]` — for a word without consonant clusters needing epenthesis, the output is unchanged. Lands in `Shwa-Caret-Gemination!CJ_2`.
8. `CONSTRUCT!H4 = "[kʰɑzɑ:d]"`, `H5 = "eVcwv9"` (Moria-font), `H6 = "tcDv9"` (Erebor-font).
9. `CONCAT!C1..C5` join with appropriate separators across all 30 word slots. With only H2 filled, the output is a single word per row.

## Open questions before Step 2

1. **Cirth → Unicode mapping**: The Cirth font characters in the Phonetics-and-Cirth sheet are Latin-keyed font glyphs. Unicode has a Cirth/Runic block at U+16A0..U+16F8 (Runic) and the Cirth-specific characters are unassigned, often handled via Private Use Area in CSUR (ConScript Unicode Registry, U+E080..U+E0FF). I'll need to build a separate mapping table by hand or by joining against an external Cirth reference. **For Step 1 we should preserve the font-keyed strings as-is** in the JSON, plus a TODO to build the Unicode mapping in a follow-up.
2. **Dictionary entry duplicates**: a quick scan of the top of column A shows several rows with the same English text (e.g. four rows of `"abdication (abandonment)"` with different Khuzdul forms `nukhru`, `nukhrû`, `nukhrul`, `nukhûr`). These are presumably different inflections / number / case. The port must return *all* matches, not just the first.
3. **Ambiguity tag inventory**: I should enumerate the universe of bracketed tags (`[Intensifying Imperfect]`, `[Imperative Plural]`, `[Imperative Singular]`, etc.) — this becomes our morphology-feature schema for free.
